# HSTU content administration — private staging candidate

**Not production-ready; no public site changes; do not merge or deploy blindly.**

This service runs independently from the existing static HSTU site. The source checkout is read-only. Editors can search existing records, add, update, remove catalogue entries or propose a replacement PDF, document reasons and review before/after values. Reviewers can export a private change bundle. Editors and reviewers collaborate in one workspace. Discarding a draft leaves the original record unchanged. No production writes, GitHub credentials, shared passwords or browser-only authentication are included.

## Ministry IT deployment gate
1. Confirm the exact Ministry production source version and hosting stack. Use Node.js 22 or a currently supported later LTS on a dedicated least-privilege service account and a private administrative host.
2. Create separate source and state directories (not ancestors or descendants of each other). Source must be a **read-only** checkout/snapshot; state must be outside every public document root, mode 0700, owned by the service account. Do not serve admin-service as static files. Keep private audit and backup data protected. Run exactly one service process; do not use clustering against its file workspace.
3. Prefer a dedicated Ministry-controlled admin origin with TLS and institutional SSO/MFA, e.g. a new approved admin subdomain; if the existing domain is used, confirm the public site's service worker and scripts cannot intercept or influence admin routes. Set the exact HTTPS origin. The application's only trusted authentication input is the `X-HSTU-Authenticated-User` header supplied by the Ministry's authenticated reverse proxy. **Never expose the loopback port to other hosts.** The proxy must require a verified Ministry identity for ALL /admin routes including JS/CSS/API, strip any client-supplied identity headers, and overwrite the header from verified SSO claims. Test forged headers, unauthenticated calls, session logout, role revocation, cross-site requests and access from unapproved identities. Use rate limiting, TLS, SSO MFA, security logging and monitoring. No demo login or default password exists.
4. Set environment variables through the server's secret manager, not Git:
   - HSTU_SOURCE: absolute path to read-only repository snapshot.
   - HSTU_STATE: private writable directory.
   - HSTU_ORIGIN: approved HTTPS origin, without path.
   - HSTU_USERS: JSON object mapping approved lowercase Ministry email addresses to editor or reviewer. Example configuration only: {"andre.griffiths@moh.gov.jm":"editor","andre.williams@moh.gov.jm":"reviewer"}. Obtain approval before provisioning.
   - HSTU_CSRF_SECRET: a private cryptographically random secret (at least 48 characters; generate locally).
   - PORT: 8787 or another approved loopback port.
5. Run `node admin-service/server.cjs`. Reverse proxy /admin and /admin/ paths to 127.0.0.1:8787 preserving paths and authenticated identity. Ensure request limits, timeouts and upload scanning policies. The app checks a PDF signature and EOF only; this is NOT antivirus scanning. Require malware scanning, approval for public release and content safety review before any attachment leaves the private workspace. NEVER upload clinical records, patient identifiers or other confidential information. The application does not provide document preview of unscanned PDFs.
6. Run `node --test admin-service/server.test.cjs` on an isolated machine, then integration and browser QA with actual Ministry proxy and source snapshot. Validate desktop/mobile, accessibility, authorization, CSRF, simultaneous edits, backup restoration, PDF handling, draft discard and exports.
7. Have IT designate reviewers and agree on a release process. The export includes original record, proposed field patch, action/reason, source hashes, audit, attachment hashes and base64 PDF bytes. It is a change request, NOT a patch or executable release. Review packages are private and must not be emailed unencrypted or publicly committed. Verify source hashes against the actual production version before applying; reconcile duplicated entries between research-catalogue.json, repository-content.json, inline MANUALS in index.html, local manual routing/fallback maps, and DATA in shanille-refinements.js. Confirm all references and PDFs, stage candidate changes, review rendered pages, test navigation, search, Gia, reader, PWA, sharing and QR, take a backup, then use approved release process with rollback. No automated application or production publishing has been enabled; direct publishing would require a separately approved deployment adapter and integration testing.
8. Restart after source snapshot changes. Existing drafts intentionally fail closed if source fingerprint differs; archive and review/rebase as an IT-managed step, never blindly reset. Back up the private state and files; audit is application-level, not tamper-proof; use institutional log retention. Review orphan PDFs and quotas periodically.

## Scope and limitations
Source adapters read research records, clinical manuals, additional JS records and structured arrays of title-bearing records in repository-content.json. Some records overlap; totals are source entries, not unique publications. Non-record HTML, gallery, service map, manual covers, inline prose and specific duplicate references are not yet fully managed automatically. Research objectives are entered numerically. An existing attachment can be marked for removal/replacement through a draft; underlying local-file deletion and all reference reconciliation remain IT release tasks. The reviewer role does not yet administer users from the UI; identities are configured by IT. Rollback is through the established release process. This is intentionally staging-only to preserve the existing live repository.

## Test gates
Do not mark production-ready until all tests run against the exact deploy candidate, Ministry SSO and staging host, and a named Ministry reviewer signs off. For rollback, simply stop this independent process/remove its proxy route; the public source is never modified by it.
